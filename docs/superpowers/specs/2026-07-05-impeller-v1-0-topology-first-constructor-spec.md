# V1.0 Topology-First Impeller Constructor Spec

**Date:** 2026-07-05

## Summary

V1.0 is a semantic rewrite of the impeller constructor. It replaces the V0.9-V0.97 pattern of building primary pressure/suction surfaces first and then repairing or stitching fillet/chamfer transition surfaces afterward.

The new construction rule is:

> The impeller is generated as a named, closed, multi-face topology from the beginning. Pressure, suction, leading-edge, trailing-edge, tip, root, hub, bore, and hub bevel/chamfer faces are all first-class NURBS or revolved-NURBS faces with shared topology edges.

In V1.0, chamfers and fillets are not generic post-processing operations. They are named topology faces generated by the blade and hub constructors themselves. The continuity contract is specified during construction and then independently measured. Shape healing, sewing, trimming, and stitched patch repair remain diagnostic/export compatibility tools, not the primary success path.

## Why V1.0 Is Needed

V0.97 is still failing because its architecture remains post-transition based. The code generates blade pressure and suction surfaces, extracts boundary derivative frames afterward, and then tries to construct transition patches by local inference. This creates recurring failure modes:

1. Tangent orientation becomes ambiguous when retained tangents are nearly orthogonal to the pressure-to-suction chord.
2. A small numerical sign change can flip a transition section tangent by 180 degrees.
3. A patch can pass endpoint and midline checks while folding internally.
4. Validation can claim measured `G2` while human inspection shows local surface inversion or missing smooth transition geometry.
5. Hub and bore chamfers are reconstructed from transition patches instead of being inherent revolve-profile faces.

The user-observed V0.97 screenshots show that incremental fixes are now exposing the same architectural defect in different places. The correct response is to change construction semantics, not add more sign guards.

## Public Evidence And Feasibility

V1.0 is consistent with public turbomachinery geometry practice.

- NASA BladeCAD represents completed blade designs as NURBS surfaces and writes standard IGES for downstream design, analysis, and manufacturing. Blade sections are defined with respect to general surfaces of revolution that represent throughflow geometry.
- The MDPI paper "Versatile Tool for Parametric Smooth Turbomachinery Blades" describes B-splines controlling meanline curvature, thickness, leading-edge shape, sweep/lean, and spanwise distributions. It emphasizes smooth curvature and reports watertight solid bodies from a parametric scheme with minimal CAD interaction.
- A unified turbomachinery parametrization paper describes axial, radial, and mixed-flow blade geometry based on typical engineering variables and NURBS curves/surfaces.
- CFturbo documentation lists failures that arise during model finishing: fillet radius too large, sharp blade edges, blade/hub/shroud tangentiality problems, failure to extend blades to hub/shroud, intersection failures, and failed blade-root fillet creation. These are exactly the failure classes expected when fillets are left to finishing operations.
- OCCT Shape Healing documentation treats wrong wire orientation, self-intersecting wires, missing seam edges, and gaps in wires as validity problems to analyze or repair. V1.0 should avoid creating these invalid shapes rather than depending on healing to rescue them.
- Rhino's GlobalEdgeContinuity command evaluates `G0`, `G1`, and `G2` along surface edge pairs. This supports V1.0's principle that continuity should be measured at named shared edges, not inferred from patch-local assumptions.

## V1.0 Semantic Contract

### V0.97 Contract

V0.97 contract:

```text
primary surfaces -> edge treatment policies -> transition patches -> trim/stitch -> validation
```

The pressure and suction surfaces are the dominant geometry. Leading, trailing, tip, root, and chamfer surfaces are transition artifacts.

### V1.0 Contract

V1.0 contract:

```text
closed blade section network -> named face network -> shared-edge topology graph -> validation/export
```

The pressure and suction surfaces are no longer privileged over the edge and root faces. The blade is a closed multi-face solid skin from the beginning.

### Required V1.0 Geometry Status

New runtime status:

```text
geometry_version = "1.0"
transition_geometry_status = "topology_first_closed_nurbs_impeller_surface_graph"
mesh_strategy = "topology_first_shared_edge_quad_patch_mesh"
kernel_capability_matrix_id = "impeller_v1_0_kernel_capabilities"
golden_case_registry_id = "impeller_v1_0_golden_cases"
```

The term `transition_geometry_status` may remain for API compatibility, but its value must make clear that V1.0 is not a transition-patch release.

## Topology Model

### Blade Face Set

Each blade instance must include these named faces:

1. `blade_{i}_pressure_surface`
2. `blade_{i}_suction_surface`
3. `blade_{i}_leading_edge_surface`
4. `blade_{i}_trailing_edge_surface`
5. `blade_{i}_tip_surface`
6. `blade_{i}_root_annular_surface`

For shrouded variants, `blade_{i}_tip_surface` may be replaced or supplemented by:

```text
blade_{i}_tip_to_shroud_interface_surface
```

Each face must declare:

- `id`
- `kind`
- `role`
- `face_family`
- `uv_grid`
- `control_net`
- `degree_u`
- `degree_v`
- `shared_edge_ids`
- `boundary_roles`
- `orientation`
- `continuity_targets`
- `continuity_measurements`

### Blade Edge Face Construction

Leading-edge, trailing-edge, and tip faces are NURBS patches, not post-fillet strips. They are generated from the same closed blade section network as the pressure and suction surfaces.

At every span station, the blade section must be a closed profile with explicit sub-curves:

```text
pressure_side_curve
leading_edge_cap_curve
suction_side_curve
trailing_edge_cap_curve
```

The profile is closed before lofting or patch generation. The leading and trailing cap curves own their curvature and thickness behavior. The edge faces are then lofted through the corresponding cap curves across stations.

### Root Annular Surface

The blade root is not a generic fillet between blade and hub. It is a named annular/root NURBS surface generated from:

- the lower blade closed-profile boundary;
- the corresponding hub attachment ring;
- a material-side root profile law;
- root leading/trailing corner coupling constraints.

The root face may be `G1` measured at the first V1.0 milestone and `G2` targeted where local topology allows it. It must not silently claim `G2` at extraordinary vertices where more than two major faces meet.

### Hub And Bore Face Set

The hub is generated from an R-Z profile graph, then revolved. Chamfers and bevels are profile segments, not later transition operations.

Required named hub faces:

1. `hub_main_revolve_surface`
2. `hub_top_face`
3. `hub_bottom_face`
4. `hub_bottom_outer_bevel_surface`
5. `mounting_bore_cylinder_surface`
6. `mounting_bore_top_bevel_surface`
7. `mounting_bore_bottom_bevel_surface`

For closed/shrouded variants:

1. `shroud_inner_surface`
2. `shroud_outer_surface`
3. `shroud_inlet_bevel_surface`
4. `shroud_outlet_bevel_surface`

The hub constructor must output named revolve-profile segments before surface graph assembly. This avoids the current V0.97 failure mode where bottom chamfers are inferred from existing transition-surface rows.

## Shared-Edge Topology Graph

V1.0 must introduce an explicit topology graph with stable edge identity.

Each shared edge must contain:

```json
{
  "edge_id": "blade_0.leading_edge.pressure_shared",
  "edge_role": "pressure_to_leading_edge",
  "incident_face_ids": [
    "blade_0_pressure_surface",
    "blade_0_leading_edge_surface"
  ],
  "node_ids": ["..."],
  "curve_3d": [[0.0, 0.0, 0.0]],
  "curve_uv_by_face": {
    "blade_0_pressure_surface": [[0.0, 0.0]],
    "blade_0_leading_edge_surface": [[1.0, 0.0]]
  },
  "orientation_by_face": {
    "blade_0_pressure_surface": "FORWARD",
    "blade_0_leading_edge_surface": "REVERSED"
  },
  "continuity_target": "G2_TARGETED",
  "continuity_status": "PASS"
}
```

No transition or mesh routine may synthesize a shared edge because two boundary curves happen to be close. Shared topology must originate in the constructor.

## Continuity Policy

### Required G0

All incident faces must share exact edge samples and topology node IDs. G0 is not a tolerance claim; it is construction identity.

### Required G1

For regular two-face blade edges:

- pressure to leading edge;
- leading edge to suction;
- suction to trailing edge;
- trailing edge to pressure;
- pressure/suction to tip;
- pressure/suction to root away from corners.

V1.0 requires measured G1. The validation tolerance should be strict enough to catch visible kinks:

```text
max_tangency_angle_deg <= 2.0
```

### Targeted G2

For regular two-face edges, V1.0 targets measured G2:

```text
max_curvature_proxy_mismatch <= configured_tolerance
```

If the constructor cannot satisfy G2 at a specific edge, it may downgrade to `G1_MEASURED` only when the surface graph records:

- edge id;
- requested continuity;
- achieved continuity;
- reason;
- local geometry limits;
- visible inspection marker.

### Extraordinary Vertices

At leading/root, trailing/root, leading/tip, and trailing/tip corners, V1.0 must avoid unsupported global G2 claims. These vertices may use corner patches or Gordon-style multi-boundary construction, but the continuity contract must be explicit:

```text
regular_edge_continuity = G2_TARGETED
extraordinary_vertex_continuity = G1_MEASURED_WITH_G2_ADJACENT_EDGES
```

## Construction Pipeline

### Stage 1: Meridional And Hub Profile

Build a named R-Z profile:

```text
hub_axis
hub_main_curve
hub_top_face_segment
hub_bottom_face_segment
hub_bottom_outer_bevel_segment
mounting_bore_segment
mounting_bore_top_bevel_segment
mounting_bore_bottom_bevel_segment
```

Then revolve each segment into a named face.

### Stage 2: Closed Blade Section Network

For each span station:

1. Generate centerline/camber law.
2. Generate pressure and suction side curves.
3. Generate leading and trailing edge cap curves.
4. Generate tip/root boundary data.
5. Enforce closed profile identity before surface generation.

The station profile must have no open curve gaps.

### Stage 3: NURBS Face Network

Construct NURBS patches by face family:

- pressure face from pressure-side curves;
- suction face from suction-side curves;
- leading edge face from leading cap curves;
- trailing edge face from trailing cap curves;
- tip face from tip cap curves;
- root annular face from root boundary and hub attachment ring.

The face network must share boundary curve objects or shared sample node IDs before validation.

### Stage 4: Topology Assembly

Build:

- face registry;
- shared-edge registry;
- vertex registry;
- incident face graph;
- boundary orientation map;
- continuity target map.

### Stage 5: Validation

Validate:

- closed section profiles;
- shared node identity;
- shared edge coordinate gap;
- wire orientation;
- face winding;
- patch foldover count;
- self-intersection proxy;
- G1 edge tangency;
- G2 curvature proxy where targeted;
- CAD export readiness;
- mesh manifoldness.

### Stage 6: Export

Export as:

- sampled surface graph for frontend;
- review OBJ/STL;
- STEP/BREP when OCCT dependencies are available;
- manifest with full topology and validation reports.

OCCT sewing may be used as a diagnostic cross-check, but a V1.0 model must not require high-tolerance sewing to become topologically meaningful.

## Frontend Requirements

The frontend must stop representing V1.0 as edge-treatment controls.

For V1.0 presets:

- hide legacy edge-treatment radius rows;
- show topology face families;
- show continuity status per shared edge;
- show named hub bevel faces;
- allow inspection modes:
  - face family;
  - shared edges;
  - continuity heatmap;
  - root annular surface;
  - hub/bore bevels;
  - topology failures only.

Root, tip, leading, trailing, and hub bevel faces must have high-contrast inspection colors that are not confused with pressure/suction/hub shading.

## Backward Compatibility

V0.9-V0.97 behavior remains available under their existing version ids. V1.0 must not silently replace old presets.

The frontend may make V1.0 the first default only after:

- open V1.0 preset validation passes;
- closed V1.0 preset validation passes;
- V0.94-V0.97 regression tests still pass;
- the user has manually inspected open and closed V1.0 examples.

## Non-Goals

V1.0 does not require:

- exact analytic OCCT fillets;
- Class-A G3 everywhere;
- perfect G2 at extraordinary vertices;
- manufacturing-ready CAM annotation;
- full CFD meshing automation.

V1.0 does require:

- topology-first named faces;
- closed blade profiles;
- shared-edge identity;
- robust validation;
- no post-hoc transition patch dependency for blade edge faces or hub bevels.

## Acceptance Criteria

### Backend

1. `radial_open_reference_v1_0` synthesizes.
2. `radial_closed_reference_v1_0` synthesizes.
3. Both report:

```text
geometry_version == "1.0"
geometry_validation_status == "PASS"
transition_geometry_status == "topology_first_closed_nurbs_impeller_surface_graph"
```

4. Every blade has the six required named faces.
5. Every hub/bore bevel is a named revolve face.
6. No V1.0 surface uses `transition_geometry` values from V0.97 edge fillet or chamfer builders.
7. Shared-edge identity gaps are below tolerance.
8. G1 continuity passes at regular blade shared edges.
9. G2 targets are measured and downgrade reasons are explicit.
10. Patch foldover count is zero.

### Frontend

1. V1.0 presets render without legacy edge-treatment controls.
2. Named face families can be isolated.
3. Shared edges can be highlighted.
4. Continuity diagnostics are visible.
5. Hub/bore bevel faces show UV wireframes.
