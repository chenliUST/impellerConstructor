**Date:** 2026-07-05


## Semantic Changes

### 1. Blade Is A Closed Multi-Face Topology

Before:

```text
pressure surface + suction surface + transition patches
```

After:

```text
pressure + suction + leading edge + trailing edge + tip + root faces
```

### 2. Leading/Trailing/Tip Faces Are Native NURBS Patches

Before:

```text
leading/trailing/tip generated by edge-treatment fillet/chamfer policy
```

After:

```text
leading/trailing/tip generated from closed blade section cap curves
```

### 3. Root-To-Hub Is A Root Annular Surface

Before:

```text
root-to-hub as generic edge fillet or blend strip
```

After:

```text
root-to-hub as dedicated annular/root NURBS face coupled to hub attachment ring
```

### 4. Hub Chamfers Are Revolve Profile Faces

Before:

```text
hub chamfer inferred from transition surface grid rows
```

After:

```text
hub bottom, bore top, and bore bottom bevels are named R-Z profile segments revolved into faces
```

### 5. Continuity Moves From After-The-Fact Repair To Constructor Contract

Before:

```text
generate patch -> measure -> try to clamp/flip/stitch
```

After:

```text
define shared edge and continuity target -> construct compatible faces -> measure and report
```

### 6. Validation Becomes Whole-Topology Validation

Before:

```text
surface-local quality fields and selected line checks
```

After:

```text
closed profile checks, shared-edge identity, face winding, patch foldover, edge continuity, mesh readiness
```

### 7. Frontend Edge Treatment Controls Are Replaced For V1.0

Before:

```text
edge treatment radius controls
```

After:

```text
topology face and continuity inspection controls
```

## Compatibility Rule

V1.0 must not overwrite V0.9-V0.97 behavior. Older presets remain versioned and available for regression comparison.

## 2026-07-05 Runtime Correction: V1.0 Is A NURBS Topology Adapter

The initial V1.0 implementation incorrectly interpreted topology-first as permission to replace the existing NURBS construction math with a new simplified primitive builder. That produced a visually wrong disk-like hub and simplified blade network.

Corrected semantic contract:

```text
V1.0 geometry math source = axisymmetric_throughflow_nurbs
V1.0 topology source = adapter over legacy NURBS surfaces
V1.0 forbidden pattern = independent primitive hub/blade generator
```

The following surfaces must preserve legacy NURBS `uv_grid` rules under the same parameters:

- `hub_revolve_surface`
- `tip_reference_surface` or `shroud_surface`
- `blade_N_pressure_surface`
- `blade_N_suction_surface`

V1.0 may rename or wrap edge-closure surfaces into:

- `blade_N_leading_edge_surface`
- `blade_N_trailing_edge_surface`
- `blade_N_tip_surface`
- `blade_N_root_annular_surface`

Those wrapped faces must derive from actual legacy blade boundary grids until V0.97 G2 blend builders are migrated into the V1.0 native topology path.

## 2026-07-05 Rule Tightening: Visibility, Deferred Hub Outer Chamfer, And Root Boss

User review of the NURBS-adapter V1.0 output showed that the topology labels were still not strict enough:

- open impeller `blade_tip_support_surface` was visible as a green reference sheet;
- hub outer chamfer faces were still generated by default even though their final topology needs a separate hub-solid rule;
- root was still a blade-material closure strip rather than a hub-to-blade annular boss;
- leading, trailing, and tip faces were still three-column closure strips and did not visibly communicate G2 transition intent.

Corrected semantic contract:

```text
open tip reference = construction reference retained in graph, hidden by default
hub bottom/top outer chamfer = deferred V1.0 feature, disabled by default
mounting bore top/bottom chamfer = retained default hub solid feature
blade leading/trailing/tip = native multisample curved G2 target patches
blade root = annular hub-projected boss surface, not blade internal bottom face
```

V1.0 now keeps the open tip reference surface for diagnostics and topology attachment, but it is marked:

```text
role = "construction_support_only"
display.visible_by_default = false
display.construction_reference = true
```

The root face keeps the stable id `blade_N_root_annular_surface`, but its role and topology are now:

```text
role = "root_pedestal_ring_surface"
root_topology = "annular_hub_to_blade_boss"
```

The outer loop is projected to the legacy revolved hub profile by theta/z. The inner loop is derived from the blade root pressure/suction/cap loop. This is still sampled review-grade geometry, but it no longer represents root as the bottom face of a blade hexahedron.

Blade transition policy defaults for V1.0 now claim `G2` only for blade transition families. Hub outer transitions are disabled:

```text
blade_leading_edge.default.continuity = G2
blade_trailing_edge.default.continuity = G2
blade_root_to_hub.default.continuity = G2
blade_tip_or_shroud.default.continuity = G2
hub_bottom_outer.default.enabled = false
hub_top_outer.default.enabled = false
```

## 2026-07-05 V1.0.2 Rule Tightening: Continuous Blade Attachment

V1.0.2 keeps the public family at `geometry_version = "1.0"` and adds:

```text
geometry_patch_version = "1.0.2"
continuous_blade_attachment_status = PASS|FAIL
```

The semantic change is not a new primitive constructor. V1.0.2 remains an adapter over the legacy NURBS math for hub, shroud/tip reference, pressure, and suction surfaces. The patch changes how the remaining blade complex is derived and validated.

New construction contract:

```text
blade_section_frame_lattice = single source for blade perimeter loops and frames
leading edge surface = G2 target patch from lattice pressure/suction leading frames
trailing edge surface = G2 target patch from lattice pressure/suction trailing frames
open tip surface = G2 target patch from lattice pressure/suction tip frames
root surface = support-domain annular boss from blade root loop to projected hub loop
closed tip surface = support-domain annular boss from blade tip loop to projected shroud loop
```

The root and closed-tip attachment surfaces are no longer treated as generic edge fillets:

```text
root role = root_pedestal_ring_surface
root_topology = support_domain_annular_attachment_boss
closed tip role = tip_to_shroud_attachment_surface
tip_topology = support_domain_annular_attachment_boss
```

Runtime defaults are now part of the contract. V1.0.2 fails closed if `resolved_attachment_defaults` are missing or malformed instead of silently using a fallback sample count.

```text
edge_short_direction_sample_count >= 17
attachment_short_direction_sample_count >= 17
root_attachment_width_mm and lift_mm must be resolved
tip_attachment_width_mm and lift_mm must be resolved
```

Validation semantics added in V1.0.2:

```text
root inner loop must match blade exterior root loop
closed tip inner loop must match blade exterior tip loop
support-domain violation count must be zero
attachment_quality.status = FAIL blocks validation
graph-level v1_0_2_transition_failures block validation
geometry_validation_report.checks includes v10_2_continuous_blade_attachment
```

Frontend inspection semantics:

```text
root_to_hub_native_root_face:
  fill = #ff00cc
  wire = #fff200

tip_to_shroud_attachment:
  fill = #00e5ff
  wire = #fff200
```

V1.0.2 attachment faces map to `edge_closures` in the layer model. Shared-edge diagnostic wires are mesh-overlay controlled and no longer stay visible when mesh overlay or mesh-edge layers are disabled.

## 2026-07-06 V1.0.2 Attachment Geometry Correction

Screenshot-driven debugging found that the previous V1.0.2 implementation met status checks but violated the intended attachment semantics. The following contracts are now explicit:

```text
support outer loop = tangentially shifted support-surface loop
support outer loop != unshifted projection at the same theta/z as blade inner loop
root/tip attachment width must be measurable in uv_grid geometry
```

The support-domain projection now uses the shifted loop as both `projected_loop` and `outer_loop`. This preserves support-surface radius/z validity while applying the requested root/tip attachment width.

Final edge caps are now topology authorities:

```text
blade_N_leading_edge_surface.edge_samples.root_profile_leading_cap = uv_grid[0]
blade_N_leading_edge_surface.edge_samples.tip_profile_leading_cap = uv_grid[-1]
blade_N_trailing_edge_surface.edge_samples.root_profile_trailing_cap = uv_grid[0]
blade_N_trailing_edge_surface.edge_samples.tip_profile_trailing_cap = uv_grid[-1]
```

The V1.0.2 attachment lattice is rebuilt after edge-surface replacement, so root and closed-tip attachments use final G2 caps rather than legacy closure caps.

Support-domain z handling is refined:

```text
small G2 cap z overrun <= resolved attachment lift -> clamp support outer loop to nearest support z boundary
G2 cap z overrun > resolved attachment lift -> support-domain violation
```

This keeps the outer loop on hub/shroud support while preserving the final G2 blade-side inner loop.

## 2026-07-06 V1.0.2 Root-Lift And Component Attachment Semantics

Root lift semantics changed from a blade-span offset to a support-normal offset:

```text
old:
  lift direction = local blade span tangent row[1] - row[0]

new:
  lift direction = outward normal of the revolved hub support profile at the blade root point
  monotonic guard = preserve a positive fraction of original span progress when the root edge moves in the same support-normal direction
```

Edge G2 section semantics changed:

```text
old:
  curvature proxy could dominate short-direction bulge direction

new:
  averaged shared-edge material normal is the primary bulge direction
  curvature proxy is retained as diagnostic input and fallback only
```

Attachment rendering semantics changed:

```text
aggregate root/tip annular support surface:
  retained for topology and diagnostics
  display.visible_by_default = false

visible support attachment surfaces:
  emitted as component patches per physical loop segment
  component_of = parent aggregate surface id
  component_segment = pressure/root-or-tip, trailing cap, suction, leading cap
```

For the open preset, the visible blade six-face complex now uses:

```text
pressure surface = original NURBS pressure side with support-normal root lift
suction surface = original NURBS suction side with support-normal root lift
leading edge = material-normal G2 review patch
trailing edge = material-normal G2 review patch
tip edge = material-normal G2 review patch
root attachment = visible piecewise support-domain component patches
```

## 2026-07-06 V1.0.3 Section-Loop Constructor

The default open preset now constructs blade faces from shared section-loop segments. It uses four main blades plus four splitter blades, a 32 mm average blade thickness, V1.0.3 section-loop defaults, segmented root blends, and open tip domes.

The frontend default cache version is now `1.0.3`, so the browser entry, App module, and preset catalog all load the active V1.0.3 model path. The manifest panel labels V1.0.3 as an active section-loop/root-blend graph, not as a deferred bootstrap.

Curve-owned transition values are no longer duplicated as scalar controls for V1.0 presets. V1.0.3 exposes editable hub/profile, blade section-loop, and open tip dome control points through `CurveControlPanel`; edits serialize through structured curve override payloads.

Root blend construction uses segmented support-domain Hermite/G2 patches. V1.0.2 remains available as historical evidence and a regression path, but it is no longer the default open inspection route.

## 2026-07-06 V1.0.3 NURBS Carrier Contract Correction

V1.0.3 section-loop topology now uses the previously validated NURBS throughflow kernel as a mathematical carrier:

```text
surface graph owner = v1_0_3_section_loop_topology_kernel
carrier source = axisymmetric_throughflow_nurbs_kernel
source math policy = section_loop_first_nurbs_carrier_blade_faces_segmented_root_blends_open_tip_domes
blade face section_loop_source = v1_0_3_nurbs_carrier_section_lattice
```

This is not a legacy graph rollback. The V1.0.3 graph still owns blade face ids, root component surfaces, open tip dome surfaces, display metadata, validation gates, and frontend topology semantics.

Root lift semantics for carrier section loops:

```text
old V1.0.3 carrier attempt:
  first loops translated along blade span tangent
  failure mode = z-domain clamp, root foldover, stale primitive-like visuals

new V1.0.3 carrier contract:
  first loops are inflated radially on the material side
  z law remains inherited from the NURBS carrier
  root solver projects outer annulus to hub support domain
```

Preset compliance change:

```text
main_streamwise_start_u: 0.08 -> 0.38
main_streamwise_end_u:   0.92 -> 0.62
splitter_streamwise_start_u: 0.38 -> 0.50
splitter_streamwise_end_u:   0.88 -> 0.59
```

Reason: a 32 mm root attachment width and 32 mm root attachment lift require hub support-domain margin. The previous extents made the blade root footprint touch hub profile boundaries and forced projection clamps/foldovers.

Open tip dome semantics changed from a fixed contraction factor to the largest non-folding contraction candidate. The default 0.42 dome contraction remains first choice; short splitter tips may use a smaller contraction while retaining positive dome height and zero foldover.

## 2026-07-08 V1.1 Blade-To-Blade Loop Surface-Family Definition

V1.1 is a semantic version change, not a V1.0.4 patch. The active V1.0.4 loop still mixes local chord coordinates with streamwise lofting, which can make the generated blade look like a primitive strip with secondary patch artifacts. V1.1 replaces that meaning with a blade-to-blade surface-family rule:

```text
geometry_version = 1.1
geometry_patch_version = 1.1.0
transition_geometry_status = topology_first_blade_to_blade_5_loop_surface_family_graph
source_kernel = v1_1_blade_to_blade_surface_family_kernel
```

Semantic changes:

```text
loop domain:
  from: local 2D chord/thickness samples mapped directly into 3D stations
  to: blade-to-blade unwrapped stream-surface domain D_h = (s, q), q = r * delta_theta

span stations:
  from: arbitrary streamwise section-loop rows
  to: five loop stations h = 0.00, 0.25, 0.50, 0.75, 1.00

main/splitter relationship:
  from: separate class scaling on the same prototype loop
  to: same D_h domain and same s-q-h to 3D map, with splitter using a shorter s interval and half-pitch phase offset

blade faces:
  from: pressure/suction/edge faces lofted from loops whose local chord direction could duplicate streamwise length
  to: pressure, suction, leading, and trailing surfaces lofted from named segment curves of the same five loop family

root surface:
  from: root annular patches inferred after blade faces exist
  to: hub attachment ribbon from hub footprint loop to the h=0 blade-to-blade loop

tip surface:
  from: open tip dome bounded after the fact by the tip loop
  to: open dome/ribbon generated from the h=1 loop; closed impellers use the same ribbon rule to attach to shroud

continuity:
  from: sampled G2 intent can be attached after curve construction
  to: C2/G2 shared jets are defined at loop joins and reused by adjacent segment curves and lofted surfaces
```

The first V1.1 implementation target keeps five span stations as the default. More stations may be added later for expert inspection, but the V1.1 contract must first prove that five loops can generate six coherent faces without local patch fixes.

## 2026-07-08 V1.1 Milestone Semantic Consolidation

V1.1 is now the active blade-to-blade loop surface-family milestone. Its semantic contract is no longer only "five loops generate surfaces"; it includes the following measured construction rules:

```text
domain = blade_to_blade_s_q_mm
s = normalized meridional streamwise coordinate
q = circumferential arc-length offset, q = r * delta_theta
h = span station from lifted root-side blade loop to tip/shroud-side loop
```

Blade population semantics:

```text
main_blade_count = 6
splitter_blade_count = 6
main_streamwise_interval_s = [0.06, 0.94]
splitter_streamwise_interval_s = [0.35, 0.88]
splitter_phase_offset_pitch = 0.5
splitter_positioning_mode = main_passage_bisector
splitter_passage_fraction = 0.5
```

The splitter semantic correction is important: a half-pitch phase offset is not sufficient when the main blade has nonzero camber at the same global `s`. Splitters are now positioned from the adjacent main-blade passage bisector, not by an independent local splitter camber curve starting at `q = 0`.

Edge cap semantics:

```text
leading/trailing edge cap measurement domain = s_mm-q_mm
default cap sagitta = 0.5 * local_thickness_mm
thin-blade cap shape = semicircular half-thickness cap
C2/G2 continuity = measured from retained boundary jets
```

Support and material semantics:

```text
root_blade_lift_mm = explicit preset/override semantic value
root attachment = ribbon from hub footprint loop to lifted blade root loop
open tip = dome/cap bounded by actual h=1 blade loop
closed shroud attachment = ribbon from blade tip loop to shroud reference loop
hub material = explicit support/material review faces including bore and bottom thickness
```
